# Ticket Management — イベント・チケット管理

GitHub Pagesで画面を公開し、Googleアカウントでログインして使います。データの保存先は次の2通りです。

- **Cloudflare版（推奨・無料）**：Cloudflare Workers ＋ D1（データベース）。スプレッドシートを使わず、1回の通信が0.1〜0.3秒程度です。メンバーはアプリの「メンバー管理」で登録します。手順は下の「Cloudflareへの移行」。
- **GAS版（旧構成）**：Google Apps Script ＋ スプレッドシート。`docs/config.js` に `apiUrl` がなく `gasUrl` だけ設定されている間はこちらで動きます。

## Cloudflareへの移行

すべてCloudflareの無料プラン（クレジットカード登録不要）の範囲で動きます。少人数のグループなら、1日あたりのリクエスト数・データベースの読み書き件数の上限には大きく余裕があります。

### 1. データベース（D1）を作る

[Cloudflareダッシュボード](https://dash.cloudflare.com/)の **Storage & Databases → D1 SQL Database → Create** で、名前を `ticket-management` にして作成します。表は初回アクセス時に自動で作られるので、SQLの実行は不要です。

### 2. Workerにコードを貼り付ける

**Workers & Pages** で、LINE連携に使っている既存のWorkerを開きます（WebhookのURLを変えずに済みます）。ない場合は **Create → Worker** で新しく作ります。**Edit code** を開き、[api/worker.js](api/worker.js) の全文に置き換えて **Deploy** します。

### 3. 設定を追加する（Settings）

| 種類 | 名前 | 値 |
|---|---|---|
| Bindings → D1 database | `DB` | 手順1のデータベース |
| Variables（テキスト） | `FIREBASE_CONFIG` | GASのスクリプトプロパティ `FIREBASE_AUTH_CONFIG` と同じJSON |
| Variables（テキスト） | `ADMIN_EMAILS` | 管理者のGoogleアカウント（複数はカンマ区切り） |
| Variables（テキスト） | `ALLOWED_ORIGINS` | `https://m0ch4771.github.io` |
| Secrets | `LINE_CHANNEL_SECRET` / `LINE_CHANNEL_ACCESS_TOKEN` | LINE通知を使う場合。LINE Developersの値 |
| Variables / Secrets | `PUSH_VAPID_PUBLIC_KEY` / `PUSH_SERVICE_ACCOUNT` | Web通知を使う場合。GASのスクリプトプロパティと同じ値（後者はSecret） |
| Triggers → Cron Triggers | — | `*/5 * * * *`（締切通知・終了イベントのアーカイブ） |

新しいWorkerを作った場合は、LINE DevelopersのWebhook URLを新しいWorkerのURLに変更します。コマンドラインで設定したい場合は [api/wrangler.toml](api/wrangler.toml) を使えます。

### 4. 画面の接続先を切り替えて、データを移行する

1. GASの `Code.gs` を最新版に差し替えて保存し、エディタで **`exportForMigration`** を選んで実行します。Googleドライブに `ticket-management-export.json` が作られるので、ダウンロードします。
2. [docs/config.js](docs/config.js) に WorkerのURLを `apiUrl` として追加します（`gasUrl` は残してかまいません。`apiUrl` が優先されます）。
   ```js
   window.LIVE_POCKET_CONFIG = {
     apiUrl: "https://ticket-management-api.<あなたのサブドメイン>.workers.dev",
     gasUrl: "…（そのまま）…"
   };
   ```
3. サイトを開き、`ADMIN_EMAILS` のアカウントでログインします（最初の1回で自動的に管理者として登録されます）。
4. 右上のアカウントメニュー → **メンバー管理** → 「スプレッドシートからデータを移行」で、ダウンロードしたファイルを選んで「移行する」を押します。イベント・参戦予定・チケット・メンバー・LINE配信設定・通知登録がそのまま移ります。
5. 移行が済んだら、GASエディタの **トリガー** 画面で `sendDeadlinePush_` と `dailyCleanup` のトリガーを削除してください（残すとLINE通知が二重に届きます）。

手順2〜4の間に他のメンバーが登録した内容は移行されません。メンバーに少しの間だけ操作を控えてもらってから切り替えてください。

### Cloudflare版での違い

- メンバーの追加・権限変更・利用停止は **アカウントメニュー → メンバー管理** で行います（管理者のみ）。スプレッドシートへの直接入力はありません。
- 保存は1つのトランザクションで行われ、全部保存されるか、まったく保存されないかのどちらかです。
- 終了したイベントのアーカイブと、30日を過ぎた保存受付の記録の削除は、5分おきのCron Triggerで行います。

## 最初の設定（GAS版・旧構成）

**管理者が初期設定とメンバーのGoogleアカウント登録を行います。**

### 1. GASにファイルを貼り付ける

[Google Apps Script](https://script.google.com/home/start)で新しいプロジェクトを作ります。

| Apps Script側 | 貼り付ける内容 |
|---|---|
| 最初からある「コード.gs」 | [Code.gs](Code.gs)の全文 |
| 「＋」→「HTML」で作る「Bridge」 | [Bridge.html](Bridge.html)の全文 |
| 「＋」→「スクリプト」で作る「Push」 | [Push.gs](Push.gs)の全文 |
| 「＋」→「スクリプト」で作る「LineWebhook」（LINE連携を使う場合のみ） | [LineWebhook.gs](LineWebhook.gs)の全文 |

名前は大文字の **Bridge** にしてください。LineWebhook.gsは、LINEのグループIDを `line-webhook/worker.js`（Cloudflare Worker）経由で自動登録するための `doPost` です。スクリプトプロパティ `LINE_WEBHOOK_SHARED_SECRET`（32文字以上）とWorker側の `GAS_WEBHOOK_SHARED_SECRET` に同じ値を設定します。古い構成のIndex.htmlは不要です。実行ボタン・キー発行・スプシの手動作成は不要です。

### 2. GASを公開してURLを取得する

「デプロイ」→「新しいデプロイ」→歯車から「ウェブアプリ」。

- 次のユーザーとして実行：**自分**
- アクセスできるユーザー：**全員**

「デプロイ」を押し、Googleの権限確認を完了します。末尾が `/exec` のウェブアプリURLをコピーします。初回接続時に管理スプシが自動作成されます。

### 3. GASのURLをGitHubに設定する

[docs/config.js](docs/config.js) の空欄にURLを入れて保存します。URLをチャットに送って反映を依頼してもOKです。

```js
window.LIVE_POCKET_CONFIG = {
  gasUrl: "https://script.google.com/macros/s/ここに発行されたID/exec"
};
```

このURLは接続先です。メンバー個人のキーやパスワードではありません。設定するのは幹事だけです。

### 4. GitHub Pagesを有効にする

リポジトリの **Settings → Pages → Build and deployment** で以下を選択します。

- Source：**Deploy from a branch**
- Branch：**main**
- Folder：**/docs**
- **Save**

公開完了後、同じ画面に表示されるサイトURLを仲間に共有します。保存先URLが未設定の間は「初期設定を準備中です」と表示されます。

### 5. Googleログインを設定する

Firebase ConsoleでAuthenticationのGoogleログインを有効にし、Authorized domainsに `m0ch4771.github.io` を追加します。GASのスクリプトプロパティ `FIREBASE_AUTH_CONFIG` にFirebase Webアプリの `apiKey`、`projectId`、`appId`、`messagingSenderId` をJSONで設定します。認証後にGASを再デプロイしてください。

既存の管理スプレッドシートのMembersシートに追加される「Googleアカウント」「権限」列を設定します。各メンバーに本人のメールアドレスを登録し、管理者を `admin`、ほかを `member` にします。未登録のアカウントは利用できません。

新しいメンバーは、Membersシートの最終行に名前とメールアドレスだけを入力すれば、本人の初回ログイン時にメンバーIDと利用状態 `yes` が自動で入ります。**メンバーIDがある行の利用状態は自動補完しません。** 空欄にすると停止扱いになり、自動で `yes` に戻ることはありません。

## 更新する時

- **画面**：GitHubの `docs/` の変更がPagesに反映されます。
- **保存処理**：Apps ScriptのCode.gs・Bridge.html・Push.gs（LINE連携を使う場合はLineWebhook.gsも）のうち、変更のあったファイルの全文を差し替えます。そのあと「デプロイを管理」→編集→「新バージョン」→「デプロイ」。同じ公開URLを使います。既存データは保持され、追加列は自動で用意されます。
- **旧版から移行**：既存のGASプロジェクトを更新すれば、スクリプトプロパティ内のスプシIDを引き続き使用し、データを保持します。追加列は自動で用意します。旧tokenHash列は残りますが使いません。

## イベント登録

日付・イベント名・会場・チケット購入ページURL・抽選締切・必要投げ数（1人あたり）の順で入力します。日付とイベント名は必須です。

続けて **出演グループを複数選択** できます。新しいグループはその場で追加し、イベントを保存すると登録済みイベントのグループが次回の選択肢に表示されます。カンマ・読点で区切って複数入力できます。最大20組、各40文字。全イベントから外れたグループは選択肢にも表示されなくなります。

グループはイベントタイルと詳細にタグ表示し、トップの検索でも探せます。関連スプシURLとメモは折りたたみ欄から登録します。

## タイムテーブルからのイベント登録

イベントタイムテーブル作成アプリでTicketDiveのイベントを読み込み、Googleスプレッドシートを作成したあと、「チケマネにイベント登録」を選ぶと、イベント登録画面にイベント名・開催日・会場・TicketDive URL・関連スプシURLが入力されます。内容を確認して保存してください。

## チケット登録

イベントカードの「番号を管理」→「＋ 番号を登録」から、整理番号を改行・空白・カンマでまとめて入力します。登録中に枚数を表示します。未発券なら番号の代わりに枚数だけ登録できます。

- 状態：未発券／自分用／余り／取引中／捌けた
- 1枚ごとの整理番号・状態・チケットURLをまとめて登録。URLは番号ごとの編集画面からも変更できます。
- 登録・編集画面から「日付／イベント名／チケット番号／URL」をまとめてコピーできます。番号一覧からは本人用URLだけをコピーできます。
- Googleアカウントに紐づいた本人のチケットだけ編集できます。
- ログイン中のメンバーに紐づくチケットを編集・削除
- 全員の参戦予定・余り枚数を確認（他のメンバーに見えるのは整理番号と状態だけです。本人用チケットURL・メモ・譲り先はサーバーから本人にしか送りません）
- 重複番号の拒否、同時更新の衝突検出

## トップのイベントカードと順序

各イベントはチケット型のカードで表示します。左の半券部分に開催日、右に「本日開催」「本日締切」「明日締切」などの目印・イベント名・会場・出演グループ・締切情報を表示し、その下で自分の参戦予定と申込状況を選べます。開催当日は黄色、抽選締切が今日・明日のイベントは赤系の半券になります。

- 「番号を管理」：自分のチケット番号の登録・状況変更
- 「みんなの予定」：全員の参戦予定・自分用/余りの枚数と、余り情報のコピー
- 「…」メニュー：イベントの編集・メモ・アーカイブ

スマホでは検索欄の横の「絞り込み」で、出演グループ・申込状況・自分の状況による絞り込みを開きます。PCでは常に表示します。

| 日本時間での表示期間 | 追加情報 |
|---|---|
| 抽選締切当日まで | 抽選締切・必要投げ数（1人あたり）・チケットURL |
| 抽選締切翌日から | 全体あまり数・関連スプシURL |

締切未設定は申込情報を表示します。全体あまり数は「余り」状態のみの合計で、自分用・取引中・捌けた・未発券は含みません。

並び順は **開催当日→抽選締切当日→抽選締切前日→その他の開催日順**。同じ優先順位内も開催日順です。開催日を過ぎたイベントは自動的にアーカイブし、参戦予定・申込状況・チケット記録を残します。

## iPhoneウィジェット（Cloudflare版のみ）

無料アプリ「Scriptable」を使って、ホーム画面・ロック画面にウィジェットを置けます。メンバーはアカウントメニューの「iPhoneウィジェット」で種類を選んで「スクリプトをコピー」し、Scriptableに貼り付けます。

- 種類：今日の締切、締切が近い順、次の締切カウントダウン（ロック画面）、次のイベント（「参戦」にしたイベントと推しグループのイベント。自分用の番号・余り枚数つき）、推しの予定（推しグループのライブ日と締切のカレンダー）
- 貼り付けるスクリプトは短い読み込み用です。本体は `docs/widget/core.js` をGitHub Pagesから読み込むので、本体を更新すれば貼り直しは不要です（通信できないときは前回の本体とデータで表示）。
- データは `GET /api/widget`（`Authorization: Bearer <メンバー専用キー>`）から取得します。返すのは本人の参戦予定・申込状況・自分用の番号と枚数・余りの枚数と、イベントの日付・締切・枠数・グループだけです。それ以外のチケット番号・URL・メモや、他のメンバーの情報は返しません。
- キーはメンバーごとに1つで、画面の「キーを作り直す」で無効にできます。利用停止にしたメンバーのキーも使えなくなります。

## 権限について

Googleログイン後、Membersシートに登録したメールアドレスと照合します。右上のアカウントメニューに現在の権限を表示し、「権限・できること」から操作範囲を確認できます。通知設定・LINE配信設定（管理者のみ）・ログアウトも同じメニューにあります。

| 権限 | できること |
|---|---|
| メンバー（`member`） | イベント一覧の閲覧・新規登録・編集・アーカイブ（すべてのイベント）、自分の参戦予定と申込状況の変更、自分のチケットの登録・編集・削除、全員の参戦状況と共有対象のチケット情報・余り情報の閲覧、自分の端末の通知設定 |
| 管理者（`admin`） | メンバーの操作に加え、LINE配信時刻と昼夜の通知内容の変更 |

管理者でも他のメンバーのチケット情報は編集できません。メンバーの登録・権限変更は管理スプレッドシートのMembersシートで行います。管理スプシをメンバーに共有する必要はありません。利用を止めるときはMembersシートの利用状態を `no` などに変更します（空欄も停止扱いです）。申込状況は「未確認」「未申込」「申込済み」「申込不要」をイベント一覧から記録できます。不参加を選ぶと申込不要になります。終了イベントは自動削除せずアーカイブし、アプリの「アーカイブを見る」から確認できます。未来のイベントはアーカイブ解除で復元できます。

## 起動時の読み込み

- 2回目以降の起動では、前回読み込んだ一覧をすぐ表示し、裏でGASから最新データを取得します。取得が終わるまで画面下に「前回の表示（未更新）」、再読込ボタンに「更新中…」と表示されます。前回の一覧はその端末に保存され、ログアウト時に消えます。
- GASとの接続準備とGoogleログインの確認を同時に始めます。ログイン設定（Firebaseの公開設定）は端末に保存し、毎回GASに問い合わせません。
- 起動時のGAS呼び出しは1回（初回ログイン時のみ3回）です。
- `Code.gs` を最新版にすると、ログイン確認の結果をトークンの有効期限まで（最大1時間）キャッシュし、保存・読み込みのたびにGoogleへ問い合わせる回数が減ります。画面側の改善はGASを更新しなくても有効です。

## 表示テーマ・アイコン

- 端末がダークモードなら自動で暗い配色になります。右上のアカウントメニューの「表示」で「自動／ライト／ダーク」を選ぶと、その端末に保存されます。
- 起動画面（半券がもぎられるアニメーション）は、その端末でその日最初に開いたときだけ表示します。端末で「視差効果を減らす」を設定している場合は動きません。
- アイコンは `scripts/icons.py` でSVGを作り、`node scripts/render-icons.mjs` でホーム画面用PNG（180／192／512px、Android用maskable）とタブ用PNGを書き出します（Playwrightが必要）。

## 開発・確認

画面はGitHub Pages、保存処理はGoogle Apps Script、保存先はスプシです。公開対象はdocs/だけです。

GASでは、名前が `_` で終わらない関数はすべて、公開URLのページから `google.script.run` で呼び出せます。Bridge.htmlの許可リストは補助的な制限にすぎないため、公開関数は必ず関数の中でログインを確認します。エディタから実行する `installDailyCleanup` などは実行者がオーナー本人かを確認し、トリガー用の `dailyCleanup` はこのプロジェクトのトリガーからの呼び出しだけを受け付けます。

すべてのテストは `for t in tests/*.cjs tests/*.mjs; do node "$t" || break; done` で実行できます（Node.js 22.5以上。Cloudflare版のテストは `node:sqlite` でD1を再現します）。

- `node tests/worker.mjs`：Cloudflare版のAPI。CORS、FirebaseのIDトークン検証（署名・対象プロジェクト・有効期限・メール確認）、管理者の自動登録とメンバー管理、イベント・参戦予定・チケットの保存と同時編集の衝突、本人以外へのチケット情報の非公開、保存受付の再送、アーカイブ、LINE Webhook・締切通知・Web通知、スプレッドシートからの移行。

- `node tests/widget.mjs`：iPhoneウィジェット（`docs/widget/core.js`）をScriptableの再現環境で描画。5種類×ホーム画面・ロック画面のサイズ、キー無効・通信できないとき・予定なしの表示。

- `node tests/backend.cjs`：Googleログイン（IDトークン検証・未登録拒否・他メンバーへのなりすまし拒否）、管理者限定のメンバー登録、利用状態の扱い、本人以外へのチケットURL・メモ・譲り先の非公開、グループ・イベント・チケット、旧版データ移行、アーカイブ、保存受付の再送・整理の確認。
- `node tests/tiles.cjs`：タイル切替・日本時間・優先順位・タグのエスケープの確認。
- `node tests/outbox.cjs`・`node tests/loading.cjs`：バックグラウンド保存キューと読み込み競合の確認。
- `node tests/transport.cjs`：iframe通信のorigin検証・IDトークンの受け渡し・Bridgeの許可リストの確認。
- `node tests/push.cjs`：プッシュ通知・LINE配信（再送キー・二重送信防止）の確認。
- `node tests/line-webhook.cjs`・`node tests/input-suggestions.cjs`：LINE Webhookと入力候補の確認。
- スマホ用の大きな操作ボタン、画面下の番号登録、固定された保存ボタン、入力破棄確認、保存失敗時の入力保持に対応。

上記のテストは模擬データで実施しています。Googleの実スプシ接続、スマホ実機の描画・操作、公開は未確認です。

## 通信方式

Cloudflare版では、画面から `https://<Worker>/api/rpc` へHTTPSでPOSTし、FirebaseのIDトークンを `Authorization` ヘッダーで送ります。Workerは毎回トークンの署名をGoogleの公開鍵で検証し、登録済みメンバーか照合します。許可するサイトは `ALLOWED_ORIGINS` で限定します。以下はGAS版の方式です。


GASの非表示iframeを介して読み書きします。Pages側はGoogleのorigin・接続ごとのランダムchannel・応答元ウィンドウを検証し、GAS側はPagesのorigin・親ウィンドウ・許可済み操作名を検証します。認証ではFirebase IDトークンを検証し、Membersシートのメールアドレスと照合します。タイムアウト時は自動再送せず、登録済みか再読込して確認します。

Code.gsのparentOriginは `https://m0ch4771.github.io` です。独自ドメインを使う場合はこの値も更新してGASを再デプロイします。外部通信の結合テストは実際のGAS URL設定後に必要です。


### スプシへの一括入力（日本語見出し）

最新版の `Code.gs` に差し替え、既存のウェブアプリのデプロイを新バージョンに更新してください。同じデプロイを編集すればURLは変わりません。更新後にサイトを開くと、各シートの見出しが日本語になります。シート名と列順は変更しないでください。

- `Lives`：イベント名・開催日（`9/20`、`2026/9/20`、`2026-09-20`）を入力した行は、次回サイト読み込み時に空欄のイベントIDと更新番号が自動補完されます。コピーで新規イベントを追加するときはイベントIDを消してください。既存イベントのIDは変更しないでください。
- 登録者IDは、`Members` の自分のメンバーIDをコピーしてください。これは自動補完されません。空欄または利用中のメンバーに存在しないIDの場合は、サイトで最初に保存したメンバーが登録者になります。
- `Members`：名前を入力した行のメンバーIDと空欄の利用状態（`yes`）も自動補完します。同名メンバーの重複登録は避けてください。
- 開催日・抽選締切は `9/20` などの月日入力にも対応。年なしの開催日は取り込み時の日本時間の年を補完し、年付きの値として保存します。翌年分は `2027/1/10` のように年を指定してください。日付セルはスプシのタイムゾーンで読み取ります。年なしの抽選締切は開催年を基準にし、開催日を超える月日は前年として扱います。必要投げ数は1人が買う枚数です。出演グループは `['グループA']` ではなく `["グループA","グループB"]` の形式です。
- `Attendance`・`Tickets` のIDや参照先は自動補完しません。参戦予定とチケットはサイトで登録してください。
- 空白行やID未発行のイベントはサイト一覧に表示しません。列の追加・移動や見出しの独自変更はしないでください。


### 終了イベントの自動アーカイブ

`Lives` の開催日が日本時間で昨日以前になった行をアーカイブします。イベント行やMembers・Attendance・Ticketsの記録は削除しません。アーカイブされたイベントはアプリのアーカイブ一覧から確認でき、開催前のイベントはアーカイブ解除で戻せます。開催日やIDが正しくないイベントはサイト一覧に表示しません。

サイトを開いた時・手動の再読込時にもアーカイブを確認します。サイトを開かない日も実行するため、GASエディタで **`installDailyCleanup` を選んで1回実行**し、権限を許可してください。実行時に既存の終了イベントもアーカイブされ、日本時間の毎日0時台に実行するトリガーが設定されます。0時ちょうどの実行を保証するものではありません。再実行しても同じハンドラーのトリガーは重複作成しません。

更新手順：Code.gsとPush.gsを全文差し替え→保存→installDailyCleanupを実行→既存デプロイを「新バージョン」で更新。新しい公開URLの発行は不要です。

トリガーの実行時間仕様：[Google Apps Script公式リファレンス](https://developers.google.com/apps-script/reference/script/clock-trigger-builder)。


### イベント編集・削除と読み込み

イベントカードの「…」メニューから「イベントを編集」を開いて編集・アーカイブできます。削除するとイベント行を削除します。削除前に確認が表示され、同時編集の更新番号も確認します。参戦予定・登録チケットの行は保持されます。

60秒ごとの自動再読込と日付監視タイマーは廃止しました。最新データはページを開く時、手動の「再読込」、自身の登録・保存時に取得します。別タブから戻るだけでは通信しません。終了イベントの日次削除トリガーはそのまま有効です。

初回接続の重複したスプシ処理を除去し、1回のリクエスト内でブックと各シートの読み取りを再利用します。通常の一覧取得はブックを1回開き、4シートを各1回取得します。日付補完・ID発行・削除などで変更があれば該当シートを取り直します。リクエストをまたぐキャッシュは使わず、手動再読込はスプシの最新値を読みます。

画面更新はGitHub Pagesに反映されます。スプシ入力イベントの編集対応と読み込み処理の改善には、最新Code.gsへの差し替え・既存GASデプロイの新バージョンへの更新が必要です。日次削除を設定済みならinstallDailyCleanupの再実行は不要です。


### 保存処理の軽量化

新しい画面は保存時に `patch-v1` の応答を要求します。GASは所有者・更新番号・番号重複を確認し、対象行を書き込み、flushが成功してから変更行と削除IDだけを返します。互換モードでは保存成功後に差分を反映します。最新版での即時表示と保存待ちは次節の方式を使用します。

保存時の日付補正・ID補完・期限切れイベントの削除、および全4シートの再読込を除去しました。これらのメンテナンスはサイトを開く時・手動の再読込・日次削除時に行います。通常のイベント編集は2シートの読み取り、1回の排他ロック、1回の書き込み確定で完了します。書き込みに不要な日付セルの内部値も読みません。既存のGASは追加引数を無視して全データを返すため、画面だけ先に更新しても動作します。以前の画面向けには全データ応答も維持しています。

保存時に他メンバーの変更を全件読み直すことはしません。他メンバーの最新データは「再読込」で取得します。最終読込日時は全件取得した時刻を示し、個別保存では変更しません。

テストは全保存操作の差分を実際の画面更新関数で適用し、再読込結果と一致すること、同時編集の拒否、旧GASとの互換性、I/O回数を確認しています。実環境での保存秒数は未計測で、GASやGoogle側の応答待ちは残ります。反映には最新Code.gsへの差し替えと既存デプロイの新バージョン更新が必要です。Bridge.htmlと日次トリガーの変更は不要です。


### 即時表示とバックグラウンド保存

最新版のGASが返す `capabilities.durableSave` とブラウザのWeb Locksに対応している場合、登録・編集を端末に保管してから画面へ即反映し、裏側で順番に保存します。保存中も他のイベントを閲覧・操作できます。同一項目への追加変更と、未保存の新規イベント・チケットに依存する保存は、先の保存が終わるまで待ちます。未保存操作は最大30件です。

一覧上部に「保存中」「送信待ち」「保存未確認」を表示し、成功が確認できた場合だけ「保存しました」と表示します。失敗時は未確認の表示変更を戻し、入力内容を端末に保持します。「再送」で同一リクエストを再送でき、「保留を解除」で入力の保留を解除できます。保留解除はサーバーの変更を取り消す操作ではありません。通信が切れた場合は再読込で実際の登録内容も確認してください。

保留データは接続先・メンバーごとにlocalStorageへ保存し、再訪時に復元します。サイトデータを削除すると端末だけに残った入力は失われます。ブラウザを閉じた間は送信が続く保証はありません。Web Locksで別タブからの保存キュー上書きを防止します。対応していないブラウザ・旧GASでは従来の保存完了待ちを使用します。

GASは管理スプシに自動作成する `SaveRequests` シートへ、書き込み前の受付と完了結果を記録します。このシートは内部管理用です。完了済みの記録は日次トリガーで30日後に削除されます（結果を確定できなかった記録は残します）。同一IDの完了済みリクエストには同じ結果を返し、再度書き込みません。受付後に処理が中断し結果を確定できない場合は `SAVE_UNCERTAIN` として再実行を止めます。この場合は再読込で確認してから保留を解除してください。これは複数シートを跨ぐトランザクションではなく、不明な状態を重複書き込みで解決しない設計です。

他メンバーへの反映はスプシへの保存完了後、その人が再読込・サイトを開き直した時です。GitHubへのデータ同期や60秒自動更新は行いません。実際のスプシへの書き込み時間を短縮する変更ではなく、画面での待ちを減らす変更です。

有効化：Code.gs・Bridge.html・Push.gsを最新版に差し替え、保存して既存ウェブアプリを「新バージョン」で再デプロイしてください。Members/Attendance列は次の接続時に自動更新されます。既存の5分おき締切トリガーを使うため、再設定は不要です。


## Googleログイン・管理者設定・申込状況

ログインには既存のFirebaseプロジェクトを使います。Firebase Consoleで **Authentication → Sign-in method → Google** を有効にし、AuthenticationのAuthorized domainsに `m0ch4771.github.io` を追加してください。GASのスクリプトプロパティ `FIREBASE_AUTH_CONFIG` に、Firebase Webアプリの `apiKey`、`projectId`、`appId`、`messagingSenderId` をJSONで設定します（既存の `PUSH_FIREBASE_CONFIG` がある場合は同じ値を利用できます）。

最初に既存のGASコードを最新版へ更新してWebアプリを再デプロイしてください。初回アクセス時にMembersシートへ「Googleアカウント」「権限」列、Attendanceシートへ「申込状況」列が追加されます。Membersシートの各メンバー行にGoogleアカウントのメールアドレスを登録し、管理者にする行の権限を `admin`、ほかを `member` にしてください。未登録アカウントはログインできません。イベントは、利用中のメンバーなら誰でも編集・アーカイブ・削除できます（「権限について」の表のとおり）。

管理者はアカウントメニューの「LINE配信設定」から昼・夜の配信時刻と通知内容を設定できます。LINE送信には `X-Line-Retry-Key` を付けるため、応答が届かずに再送した場合も同じメッセージが二重に投稿されません。時刻は5分単位で、昼の時刻は夜より1時間以上前にします。夜の「申込状況が未確認の人」通知では、締切イベントごとに「申込済み」「申込不要」を選んでいないメンバーが表示されます。締切当日のイベントカードでは、自分の申込状況を「未確認」「申込済み」「申込不要」から記録できます。
