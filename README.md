# LIVE POCKET

仲間内のライブ参戦・余りチケット管理。ソースはGitHubで管理し、Webアプリとデータの読み書きはGoogle Apps Script（GAS）、保存先は非公開のGoogleスプレッドシートです。GitHub Pagesへの公開は不要です。

## 実装した機能

- ライブ登録・登録者による編集（日付、抽選締切日、必要投げ数、会場、メモ、関連スプシURL）
- メンバー個別キーでログイン、自分の参戦・未定・不参加を更新
- 全員の参加状況、所有者ごとの余り枚数
- 整理番号を改行・カンマ・空白でまとめて登録、番号順で表示
- 未発券は枚数だけ登録し、発券後に各番号を編集
- 1枚ごとに未発券／自分用／余り／取引中／捌けた、譲り先とメモ
- 状態・自分のチケットで絞り込み、誤登録の削除
- 60秒ごとの読込、自分のチケットだけ編集可能
- サーバー側の重複番号検証、同時更新ロック、編集の競合検出

## 最初の設定

1. https://script.google.com/ で新規プロジェクトを作成。
2. `Code.gs`を貼り付け、HTMLファイルを`Index`という名前で作り`Index.html`を貼り付け。
3. プロジェクト設定でマニフェストを表示し、`appsscript.json`を反映。
4. エディタで `setup_` を1回実行してGoogleの権限確認を完了。管理スプレッドシートが新規作成され、URLが実行ログに表示されます。IDはスクリプトプロパティに保存されます。
5. `issueMember_` 内の `name` を本人の呼び名に変えて実行。ログに出たメンバーキーをその人だけに共有。各メンバーについて繰り返します。同名でも別メンバーなので、重複発行しないでください。
6. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」。実行するユーザーは自分。仲間がアクセスできる公開範囲を選択します。アプリ内の閲覧・更新には別途メンバーキーが必須です。
7. `/exec` のURLを開き、自分のキーでログイン。ライブを作成し、参戦予定とチケットを登録。
8. 更新時は「デプロイを管理」から新しいバージョンに更新します。

Google側のアカウント作成、認可、デプロイはまだ行っていません。Googleに接続して確認するまで運用開始しないでください。

## 管理スプシ

| シート | 用途 |
|---|---|
| Lives | ライブ名・日付・会場・関連スプシURL・抽選締切日・必要投げ数 |
| Members | メンバー・キーのSHA-256ハッシュ・有効状態 |
| Attendance | ライブごとの参戦予定 |
| Tickets | チケット1枚につき1行 |

関連スプシはリンクとして保存します。関連スプシ内の任意の表を自動取り込みする機能ではありません。管理用の4シートがアプリの保存先です。

メンバーはアプリから操作し、管理スプシは幹事だけが編集できる設定を推奨します。メンバーキー原文をGitHubやスプシに保存しないでください。キーはブラウザのタブのセッションに保持し、退出で削除します。キーを失効させる場合はMembersの該当行のactiveをyes以外に変更してください。

任意の参加者がライブを登録でき、ライブ編集は登録者だけ、チケット編集は所有者だけ可能です。全員が全メンバーの番号・譲り先・メモを閲覧できます。スプシを直接変更する場合はidやversion列、ヘッダーを維持し、他の人が操作していないときに行ってください。直接のスプシ編集はアプリの検証・ロックの対象外です。

## 抽選締切日・必要投げ数

ライブの登録・編集で両方を設定でき、一覧と詳細に表示します。いずれも任意入力で、空欄は「未設定」です。必要投げ数は、そのライブで1人が購入する枚数として扱い、0以上の整数を登録します。例えば5と登録すると「1人あたり5枚」という意味です。抽選締切日は日付のみで、通知や受付の自動停止はしません。

旧版で管理スプシを作成済みの場合は、更新したCode.gsで `migrateLives_` を1回実行してから新しいバージョンを公開してください。Livesの既存8列を維持し、I列にlotteryDeadline、J列にrequiredThrowsを追加します。既存ライブは未設定として表示されます。新規設定ではこの作業は不要です。

## イベント登録から各メンバーの番号入力まで

1. イベント登録で、日付・イベント名・会場・チケット購入ページURL・抽選締切・必要投げ数（1人あたり）の順に入力します。日付・イベント名は必須、未確定の項目は後で編集できます。
2. 関連スプシURLとメモは任意の折りたたみ欄にあります。
3. メンバーは自分のキーで入り、対象イベントを選びます。
4. 参戦予定を選択し、「自分の番号を登録」で自分の整理番号を入力します。複数番号の一括入力も可能です。登録者はログイン中の本人に自動で紐づきます。
5. 各チケットを自分用・余り・取引中・捌けたなどに更新します。

チケット購入URLはLivesのK列（purchaseUrl）に保存します。既存スプシをご利用の場合、今回の更新後にも `migrateLives_` を実行してください。既存の抽選締切・必要投げ数を保持してK列を追加します。

## トップページのタイル

日付・イベント名・会場は常時表示します。日本時間で抽選締切当日までは抽選締切・必要投げ数（1人あたり）・チケットURLを表示し、翌日0時から全体あまり数・関連スプシURLに切り替えます。締切未設定のイベントは申込情報を表示します。URL未設定はその旨を表示します。全体あまり数は全メンバーの「余り」状態のチケット合計です（自分用・取引中・捌けた・未発券は含みません）。

優先順位は開催当日→抽選締切当日→抽選締切前日→その他の開催日昇順です。複数条件に該当するイベントは最上位の条件を適用し、同じ優先順位内は開催日順です。過去のイベントもその他に含めて開催日順に表示します。タイルの「詳細・自分の番号を登録」から個別画面へ進みます。表示切替は日本時間の日付変更時にも更新します（編集中は保存・終了後）。

## スマホ操作の改善

- 主な操作ボタンは高さ48px以上（補助ボタン・状態絞り込みは44px以上）。
- 小さい画面ではイベントタイルを1列表示し、締切・1人あたり枚数を並べて表示。
- イベント詳細の下部に「自分の番号を登録」を固定。参加者一覧は折りたたみで表示。
- 登録・編集画面はスマホでは下から開く形式で、保存・閉じる操作を固定。
- 整理番号入力中に登録枚数を表示。未発券選択時のみ枚数入力に切り替え。
- 入力途中で閉じる場合は破棄確認。保存失敗時は入力を保持し、画面内にエラーを表示。
- 保存中の二重操作を抑止し、検索入力中・ダイアログ表示中は定期読込を保留。
- 一覧に戻ると元のスクロール位置に復帰。
