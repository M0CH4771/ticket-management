締切通知の初期設定

管理者が一度だけ行う設定です。メンバーは設定後、サイトの「通知設定」から許可するだけです。

FirebaseのSpark（無料）プランを使用します。Blazeへの変更・支払い方法の登録・Cloud Functions・Firestoreは不要です。

LINE通知を有効にする

送信先は、Botを招待した1つのグループに固定します。サイトにLINEの設定項目はありません。締切当日のイベントをまとめて1回送り、本文には「本日締切／開催日／イベント名／チケットURL／枠数」を載せます。

LINEの認証情報はGASとCloudflareにだけ保存します。チャネルシークレットとアクセストークンは、GitHubやチャットへ貼らないでください。チャネルシークレットを以前どこかに貼った場合は、LINE Developersで再発行してから使ってください。

1．GASにグループID受取コードを追加

  1. チケット管理に使っているApps Scriptを開き、「＋」→「スクリプト」を選び、名前を LineWebhook にします。
  2. 下のコードをコピーして貼り、保存します。

  3. Apps Scriptの「プロジェクトの設定」→「スクリプト プロパティ」で、LINE_WEBHOOK_SHARED_SECRET を追加します。パスワード管理アプリでランダムな長い文字列を作ってください（32文字以上）。この値は後でCloudflareにも同じものを設定します。ここやチャットへ貼らないでください。
  4. 「デプロイ」→「デプロイを管理」→鉛筆→「新バージョン」→「デプロイ」で更新します。既存のウェブアプリURLは変わりません。

2．Cloudflare Workerを作る

  1. Cloudflareにログインし、「Workers & Pages」→「Create」→「Create Worker」からWorkerを作り、名前を ticket-line-webhook などにします。
  2. 作成したWorkerの「Edit code」を押し、最初のコードを全て消して、下のコードを貼り付けて「Deploy」します。

  3. Workerの「Settings」→「Variables and Secrets」で、以下の3つを追加します。秘密値はSecretとして登録してください。
  • LINE_CHANNEL_SECRET：LINE DevelopersのMessaging APIチャネルにあるチャネルシークレット（未ローテーションの場合は再発行後の値）。
  • GAS_WEB_APP_URL：チケット管理GASのウェブアプリURL。サイトの設定にある gasUrl と同じURL。
  • GAS_WEBHOOK_SHARED_SECRET：手順1で作った同じランダム文字列。

もう一度「Deploy」します。表示される https://…workers.dev のURLを控えます。これがLINEのWebhook URLです。

3．LINE DevelopersでWebhookをつなぐ

  1. LINE Developers Consoleで、対象のMessaging APIチャネルを開きます。「Messaging API設定」の「Webhook URL」にWorkerのURLを貼り、「更新」→「検証」を押します。
  2. 検証が成功したら「Webhookの利用」をオンにします。Botを招待する前にここまで済ませます。
  3. Messaging APIチャネルの「チャネルアクセストークン（長期）」を発行します。チャットへ貼らず、次のGASプロパティへ直接入力してください。

4．グループを1つだけ登録して通知を有効化

  1. LINE公式アカウントの設定で、Botがグループに参加できるようにします。
  2. 通知したいグループへBotを招待し、そのグループで誰かがメッセージを1回送ります。WebhookがグループIDをGASへ自動登録します。先に別のグループへ招待しないでください。送信先を変える場合は、管理者がGASの LINE_GROUP_ID プロパティを削除してから、目的のグループでやり直します。
  3. GASのスクリプト プロパティに LINE_CHANNEL_ACCESS_TOKEN として長期アクセストークンを登録します。
  4. GASエディタで installLineNotifications_ を選んで実行し、アクセスを許可します。成功ログが出れば設定完了です。確認用のLINEメッセージは送信しません。
  5. 既存のウェブアプリを「デプロイを管理」から新バージョンへ更新します。

この設定は最初の1回だけです。サイトにLINEの設定ボタンやグループ選択は追加しません。Botは1つのグループにだけ招待してください。

1．Firebaseの無料プロジェクトを作る

  1. Firebaseコンソールでプロジェクトを作成します。名前の例：Ticket Management。Google Analyticsは不要です。
  2. プロジェクトに「ウェブアプリ（</>）」を追加。Firebase Hostingの設定は不要です。
  3. 表示される firebaseConfig の中から apiKey・projectId・messagingSenderId・appId の4項目を控えます。
  4. プロジェクトの設定 → Cloud Messaging → ウェブプッシュ証明書で鍵ペアを生成し、表示された公開鍵を控えます。
  5. 同じ画面で「Firebase Cloud Messaging API（V1）」が有効か確認します。無効なら、案内先のGoogle Cloudで有効にします。Firebase Installations API・FCM Registration APIも有効にしてください。
  6. プロジェクトの設定 → サービスアカウント → Firebase Admin SDK → 新しい秘密鍵を生成し、JSONファイルを保存します。このファイルの中身はGitHubやチャットに貼らず、次のGAS設定にだけ入れます。

2．今のGASへ通知機能を追加する

チケット管理に使っているApps Scriptを開きます。既存の Code.gs は変更しません。

  1. 「＋」→ スクリプトで Push を追加し、下のコードを貼り付けます。

  2. 既存の Bridge.html を下の内容に置き換えます。

  3. プロジェクトの設定 → スクリプトプロパティで、以下の3つを追加します。
  • PUSH_FIREBASE_CONFIG：4項目をまとめたJSON。下の形式で値を入れ替えます。JavaScriptの const firebaseConfig = は付けません。
  • PUSH_VAPID_PUBLIC_KEY：ウェブプッシュ証明書の公開鍵。
  • PUSH_SERVICE_ACCOUNT：ダウンロードしたサービスアカウントJSONの全文。既存のスクリプトプロパティは削除しません。
{
  "apiKey": "コピーした値",
  "projectId": "コピーした値",
  "messagingSenderId": "コピーした値",
  "appId": "コピーした値"
}

保存後、GASエディタ上部で enableNotifications を選んで実行し、Googleの権限を許可します。5分ごとのトリガーが1つ作成されます。

デプロイ → デプロイを管理 → 編集 → 新バージョンで、現在のウェブアプリを更新します。既存のURLを維持し、実行ユーザーとアクセス設定も今のままにします。

3．スマホで通知をオンにする

  1. iPhoneはSafariでサイトを開き、「共有」→「ホーム画面に追加」。iOS 16.4以降が必要です。
  2. 追加したアイコンから起動し、イベント一覧の下の「通知設定」を開きます。
  3. 「通知を受け取る」を押し、通知を許可します。
  4. 「テスト通知」を押して、実際に届くか確認します。画面を閉じた状態でも通知を確認してください。

通知は端末ごとの設定です。「すべてのグループ」または「グループを選ぶ」で通知対象を設定できます。選んだグループが同じイベントに複数出演していても、イベントは1回だけ掲載します。参戦状況とは別の設定です。

通知の動作

  • 日本時間の昼12時以降に、締切当日のイベントがある日だけ送信します。12時ちょうどの配信は保証されません。
  • 端末ごとに、その日の送信成功を記録します。通信エラーは15分以上あけて最大3回試行します。同日の通知は同じタグで置き換えます。
  • 当日分の通知を送った後にイベントを追加しても、その日の再送はしません。
  • 期限切れの通知先は停止します。通知が届かなくなったら「通知設定を保存」を押してください。
  • 初期設定では100端末まで、1回の実行につき最大10端末へ送信します。多数の端末では順次配信になります。
  • 無料のGAS利用上限に達した場合は遅延・停止することがあります。自動で有料プランに移行する構成ではありません。
  • 全体の通知を止めるにはGASで stopPushNotifications_ を実行します。各自は「通知をオフ」で停止できます。
